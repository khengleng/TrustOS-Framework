# Pilot validation — Merchant Wallet Basic

A reference application built to answer one question: **can TrustOS produce, secure and operate a
real financial product without rebuilding what it already provides?**

Not whether the framework compiles, and not whether a demo can be made to work. Whether an
application team, building an ordinary payment acceptance product, ends up writing a ledger, a
limit engine, an idempotency layer and a permission model of their own — because that is what
happens when a framework is almost enough.

## The result

**GO for the next pilot**, with the remediations in [`production-readiness.md`](production-readiness.md).

Not go for production banking use. See [§ What this does not establish](#what-this-does-not-establish).

## What was built

A merchant payment acceptance product: register a merchant, verify it, approve it through
maker-checker, open a ledger-backed wallet, accept a mock payment, price it, post it, settle it and
reconcile it — with tenant isolation, limits, an API gate, an audit trail, objectives and an AI
assistant that cannot act.

## What this does not establish

Stated here rather than in a footnote, because the sentence that gets quoted from a pilot report is
usually the summary.

**Nothing was deployed.** The pilot runs in a test process against in-memory stores. Every port has
a Prisma implementation in the framework and the pilot binds none of them, so nothing here says
anything about the application under a real database, a real network or real concurrency across
processes.

**No backup was taken, no restore was performed, and no DR exercise was run.** There is no
database and no deployment to take one of. Those three sections of the pilot specification are
reported as NOT PERFORMED rather than estimated, and the readiness scorecard marks them FAIL rather
than PARTIAL — a plan with no exercise behind it is documented, not demonstrated.

**No real payment rail was integrated**, by instruction. Every provider is a declared mock.

**The performance numbers measure application logic, not a system.** One process, in-memory stores,
no HTTP and no database. A production p95 will be larger and will be dominated by the two things
this measurement excludes.
